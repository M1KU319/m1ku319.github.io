Convex Hull Trick

Convex Hull Trick

The Convex Hull Trick can speed up a dynamic programming transition by treating each previous state as a line. In this post, we will derive this transformation for a partitioning problem and explain how a monotonic deque reduces the running time from O(n2)O(n^2) to O(n)O(n).

Problem analysis

Starting with a quadratic DP

Consider HNOI2008 Toy Packing.

There are nn items arranged in a line. The ii-th item has length cic_i, and we need to partition the items into contiguous groups. For a group [l,r][l,r], the cost is

(r−l+∑k=lrck−L)2, \left(r-l+\sum_{k=l}^{r}c_k-L\right)^2,

where LL is a constant. The term r−lr-l accounts for the one-unit gap between each pair of adjacent items in the group. Our goal is to minimize the total cost of all groups.

The constraints are

1≤n≤5×104,1≤L,ci≤107. 1\le n\le 5\times 10^4,\qquad 1\le L,c_i\le 10^7.

Let fif_i denote the minimum total cost of partitioning the first ii items. Define the prefix sums as

Si=∑k=1ick,S0=f0=0. S_i=\sum_{k=1}^{i}c_k,\qquad S_0=f_0=0.

If the final group contains items j+1j+1 through ii, its total length is Si−Sj+i−j−1S_i-S_j+i-j-1. Considering every possible starting position of this final group gives the recurrence

fi=min0≤j<i{fj+(i−(j+1)+Si−Sj−L)2}=min0≤j<i{fj+(Si−Sj+i−j−1−L)2}. \begin{aligned} f_i &=\min_{0\le j<i}\left\{f_j+\left(i-(j+1)+S_i-S_j-L\right)^2\right\}\\ &=\min_{0\le j<i}\left\{f_j+\left(S_i-S_j+i-j-1-L\right)^2\right\}. \end{aligned}

This straightforward solution checks every previous state for each ii, resulting in an O(n2)O(n^2) algorithm.

Rewriting the transition

Expanding the square allows us to separate the terms that depend only on ii from those involving jj.

Let ai=Si+ia_i=S_i+i. We can then write

Si−Sj+i−j−1−L=ai−aj−L−1. S_i-S_j+i-j-1-L=a_i-a_j-L-1.

Now let xi=ai−L−1x_i=a_i-L-1. The recurrence becomes

fi=min0≤j<i{fj+(xi−aj)2}=xi2+min0≤j<i{−2ajxi+fj+aj2}. \begin{aligned} f_i &=\min_{0\le j<i}\left\{f_j+(x_i-a_j)^2\right\}\\ &=x_i^2+\min_{0\le j<i}\left\{-2a_jx_i+f_j+a_j^2\right\}. \end{aligned}

For a fixed ii, the term xi2x_i^2 is the same for every candidate jj, so it can be moved outside the minimum.

Interpreting each state as a line

For each previous state jj, define a line

ℓj(x)=kjx+bj, \ell_j(x)=k_jx+b_j,

where

kj=−2aj=−2(Sj+j),bj=fj+aj2=fj+(Sj+j)2. k_j=-2a_j=-2(S_j+j),\qquad b_j=f_j+a_j^2=f_j+(S_j+j)^2.

Computing fif_i now requires finding the minimum value among these lines at x=xix=x_i, then adding xi2x_i^2:

fi=xi2+min0≤j<iℓj(xi). f_i=x_i^2+\min_{0\le j<i}\ell_j(x_i).

Once we have computed fif_i, we can construct its line and make it available to subsequent states. We query before inserting the new line because only states with j<ij<i are valid candidates.

Maintaining the candidate lines

To speed up the transition, we discard lines that cannot improve the answer to any future query. However, we cannot keep only the line that is currently optimal: a different line may become optimal as the query coordinate changes.

We will use a deque under two conditions:

  • Lines are inserted in strictly decreasing order of slope.
  • Query coordinates are nondecreasing.

The first condition lets us remove redundant lines from the back of the deque. The second lets us discard lines from the front as we answer queries.

Adding a new line

Consider three lines PP, QQ, and RR with strictly decreasing slopes:

kP>kQ>kR. k_P>k_Q>k_R.

The xx-coordinate of the intersection of PP and QQ is

X(P,Q)=bQ−bPkP−kQ. X(P,Q)=\frac{b_Q-b_P}{k_P-k_Q}.

For QQ to be no higher than both PP and RR, we need

X(P,Q)≤x≤X(Q,R). X(P,Q)\le x\le X(Q,R).

Therefore, if

X(P,Q)≥X(Q,R), X(P,Q)\ge X(Q,R),

then QQ is never strictly better than both PP and RR. When the two intersection coordinates are equal, all three lines meet at the same point, so QQ can still be removed without changing the minimum value.

When inserting a new line RR, we apply this test to the last two lines in the deque and RR. If the middle line is redundant, we remove it from the back and repeat the test. We then append RR.

Answering queries

Suppose the first two lines in the deque are PP and QQ, with kP>kQk_P>k_Q. If, at the current query coordinate xx,

Q(x)≤P(x), Q(x)\le P(x),

then QQ remains no higher than PP for every later coordinate. To see why, let x′≥xx'\ge x. We have

Q(x′)−P(x′)=Q(x)−P(x)+(kQ−kP)(x′−x)≤0. Q(x')-P(x')=Q(x)-P(x)+(k_Q-k_P)(x'-x)\le 0.

We can therefore remove PP from the front of the deque. We repeat this comparison until only one line remains or the first line is better than the second at the current coordinate.

The insertion step keeps the intersection coordinates of consecutive lines in increasing order. This ensures that, once the front comparisons stop, the first line gives the minimum value among all remaining candidates.

Applying the optimization

Returning to our problem, we have

ai+1−ai=ci+1+1>0. a_{i+1}-a_i=c_{i+1}+1>0.

Thus, aia_i is strictly increasing. The inserted slopes kj=−2ajk_j=-2a_j are strictly decreasing, and the query coordinates xi=ai−L−1x_i=a_i-L-1 are strictly increasing. Both conditions required by the deque are satisfied.

Each line is inserted once and removed at most once, from either end. Although a single operation may remove several lines, there are only O(n)O(n) removals over the entire algorithm. The total running time is therefore O(n)O(n), with O(n)O(n) space in the worst case.

Understanding the implementation

Matching the code to the recurrence

The implementation below uses an equivalent arrangement of the same recurrence. It keeps the query coordinate at aia_i and includes the constant L+1L+1 in each line instead.

Define

tj=aj+L+1. t_j=a_j+L+1.

Then

fi=min0≤j<i{fj+(ai−tj)2}=ai2+min0≤j<i{(−2tj)ai+fj+tj2}. \begin{aligned} f_i &=\min_{0\le j<i}\left\{f_j+(a_i-t_j)^2\right\}\\ &=a_i^2+\min_{0\le j<i}\left\{(-2t_j)a_i+f_j+t_j^2\right\}. \end{aligned}

The code therefore uses the following quantities:

Code Meaning
s[i] The prefix sum SiS_i.
f[i] The minimum cost fif_i.
x = s[i] + i The current query coordinate aia_i.
t The value tj=aj+L+1t_j=a_j+L+1 for the state whose line is being constructed.
line.fir The slope −2tj-2t_j.
line.sec The intercept fj+tj2f_j+t_j^2.

Here, fir and sec are macros for first and second. The deque stores each line as a pair containing its slope and intercept. Since adding L+1L+1 preserves the order of the aja_j values, the slopes still decrease and the query coordinates still increase.

Initializing the deque

The initial candidate is state j=0j=0, where a0=f0=0a_0=f_0=0. Therefore, t0=L+1t_0=L+1, and its line is

y=−2(L+1)x+(L+1)2. y=-2(L+1)x+(L+1)^2.

This explains the initialization t = L + 1 and q.push_back({-2 * t, t * t}). State 00 represents placing all of the first ii items into a single group. The global arrays are zero-initialized, providing s[0] = f[0] = 0.

Querying the minimum

The helper value(line, x) evaluates a line at the current coordinate. In the first while loop, if q[1] is no higher than q[0], the first line can be removed permanently. The <= comparison also handles ties: the second line has a smaller slope and is at least as good for every future query.

After this loop, q.front() gives the minimum line value, so the assignment f[i] = x*x + value(q.front(), x) computes the current DP state.

Inserting the current state

After computing f[i], the code sets t = x + L + 1. Since x = a_i, this is exactly ti=ai+L+1t_i=a_i+L+1. The new line R has slope −2ti-2t_i and intercept fi+ti2f_i+t_i^2.

The helper check(A, B, C) determines whether the middle line B is redundant. It tests

X(A,B)≥X(B,C). X(A,B)\ge X(B,C).

Because kA>kB>kCk_A>k_B>k_C, both denominators in the intersection formulas are positive. We can therefore compare the intersections by cross multiplication:

(bB−bA)(kB−kC)≥(kA−kB)(bC−bB). (b_B-b_A)(k_B-k_C)\ge(k_A-k_B)(b_C-b_B).

This is the expression used in check, avoiding division when comparing intersection coordinates. The second while loop removes redundant lines from the back, and q.push_back(R) makes the new state available to future queries.
