History in Numbers

Problem summary:

Given a sequence aa, treat consecutive equal values as a single value. We need to support the following two operations:

  • Add dd to every element in an interval.
  • Query an interval [s,f][s, f] and check whether its local minima are strictly increasing from left to right.

An element is a local minimum if it is smaller than both of its neighbours. At either end of the sequence, we only compare it with its one neighbour.

Constraints:

  • Sequence length: 1≤n≤3*1051 \le n \le 3 * 10^5, −108≤ai≤108-10^8 \le a_i \le 10^8
  • Number of operations: 1≤m≤3*1051 \le m \le 3 * 10^5, |d|≤108|d| \le 10 ^8

Obviously, another delightful segment tree problem. (Just kidding.)

Choosing what to maintain

We need to work out what information lets us detect new local minima during a merge and check whether the resulting sequence of local minima is ordered—strictly increasing, as the problem requires. A simple lazy tag will take care of range addition.

Let’s start with merging two intervals. A new local minimum may appear where they meet, so the left and right endpoints of an interval are potential local minima. To decide whether they become local minima, we need to maintain both their values and the direction of change near each endpoint.

We also need to know whether the merged sequence of local minima is strictly increasing. So we store the first and last local minima of each interval as well. During a merge, we only need to compare the values at the joins between these sequences.

Treat consecutive equal elements as one, then exclude the two endpoints: we only store the internal local minima.

Merging the local-minimum information

Let’s start with the easy part. We will need to merge the information from two intervals several times, while keeping track of whether the sequence of local minima is strictly increasing. Call the two adjacent intervals x and y. If both are ordered, and the last local minimum of x is smaller than the first one of y, then the merged sequence is strictly increasing too.

Handling new local minima when merging nodes

Let lval and rval be the values at the left and right endpoints. Reading from left to right, l and r record the first and last non-zero directions of change: 1 means increasing and -1 means decreasing. If there is no change, the direction is 0.

For two adjacent intervals u and v, there are three cases:

  • u.rval < v.lval: the right endpoint of the left interval becomes a new local minimum if and only if that interval is decreasing near its right endpoint, i.e. u.r == -1.
  • u.rval > v.lval: the left endpoint of the right interval becomes a new local minimum if and only if that interval is increasing near its left endpoint, i.e. v.l == 1.
  • u.rval == v.lval: the two endpoints in the middle can be merged into one local minimum if and only if u.r == -1 && v.l == 1.

Range updates and lazy propagation

It is not hard to see that adding the same value to an interval does not change the relative order of its elements. The local minima all receive the same offset, so whether their sequence is strictly increasing stays unchanged. New local minima may appear only at the boundaries of the updated interval.
