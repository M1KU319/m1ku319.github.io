Dinic & Maximum Bipartite Matching

Read the original Chinese version

In EK, each BFS finds one augmenting path. After pushing flow along it, we start searching again. The problem is that this BFS has already found the shortest distances to many vertices, but we only use one path in the end. That feels like a bit of a waste.

Could we keep the search results, find a few more augmenting paths of the same length, and only then run BFS again? Dinic takes this idea further.

First, divide the residual network into levels

Let level[u] be the minimum number of residual edges needed to reach u from the source. BFS still only follows edges with positive residual capacity. Once we have the levels, we add one more condition to DFS.

In other words, each step must move to the next level. The graph formed by these edges is called the level graph.

When we reach the sink this way, the number of edges we have used must equal level[t], so we have found a shortest augmenting path. Levels strictly increase along the path, which also means DFS cannot go around a cycle. There is no need for the usual vis array.

What we divide into levels here is the current residual network. Both original edges and reverse edges take part in BFS, as long as they have remaining capacity. If a reverse edge happens to go from level kk to level k+1k+1 in this round, it can also belong to the level graph.

How much can we get out of one BFS?

With the levels fixed, we repeatedly run DFS from the source. Each time we find a path, we push its bottleneck flow, until DFS returns 0.

At this point, every source-to-sink path in the current level graph has at least one saturated edge. We can no longer augment by moving through increasing levels. The flow sent in this round is called a blocking flow.

A blocking flow only needs to block these current paths. It does not have to be a maximum flow of the level graph itself. Finding that maximum flow might require undoing earlier choices in this round, and undoing them would use reverse edges that go against the current level direction.

In the next round, we run BFS on the updated residual network. All the old shortest paths have been blocked, so if an augmenting path still exists, it must be longer. The highest possible level is V−1V-1, which gives at most O(V)O(V) rounds of building the level graph.

In code, this is just two while loops.

The inner loop uses up the current level graph, and the outer loop builds a new one. Each DFS only needs to return the flow along one path. There is no need to force all paths into a single recursive call just because we call the result a “blocking flow”.

Why can the current-edge pointer keep moving forward?

If we start from the first outgoing edge every time we enter u, we will check the same unusable edges again and again. So we keep a cur[u] for each vertex, recording the position in id[u] of the next edge to try.

The & matters here. Changing i inside the loop also changes cur[u], so the next visit to u can continue from where we left off.

Why is it safe to skip an edge that has already failed? Consider one augmentation along the level graph. The forward residual capacity decreases, and any newly added reverse capacity points to the previous level, so this round’s DFS cannot use it. The usable forward edges in this round can therefore only disappear; no new ones become available. Once a vertex has no remaining path to the sink, further augmentations cannot make it reach the sink again.

After successfully pushing flow, the current edge may still have capacity. We therefore use return pushed directly and leave the pointer on this edge. The loop only moves on when the edge is saturated or there is no longer a path to the sink through it.

This reasoning depends on level staying fixed. When the next BFS changes the levels, every cur must be reset to zero.

Using Dinic for maximum bipartite matching

Suppose there are nLn_L vertices on the left and nRn_R vertices on the right. Each allowed pair connects the two sides. We want to choose as many pairs as possible, with each vertex chosen at most once.

Start with a single matched pair. If one unit of flow passes through a left vertex, then a right vertex, and finally reaches the sink, it can represent choosing that pair.

The diagram only shows original edges. When building the graph, each edge still needs a reverse residual edge. Every original edge has capacity 1.

Edge Constraint
s -> u Left vertex u can appear in at most one matched pair
u -> nL+v The pair (u,v) is allowed
nL+v -> t Right vertex v can appear in at most one matched pair

Both sides may be numbered from 1 in the problem, so we add nL to every right-side index. Set s=0 and t=nL+nR+1. The whole network then needs nL+nR+2 vertices.

Every valid matching can be turned into an integer flow of the same size. In the other direction, the algorithm starts with zero flow and pushes an integer amount in each augmentation. A pairing edge with capacity 1 will therefore carry either 0 or 1 unit at the end. The capacities next to the source and sink also ensure that each vertex is used at most once. So an integer flow can be turned back into a matching, and the maximum flow value equals the maximum matching size.

What do reverse edges do in a matching?

Consider just three allowed pairs: L1R1L_1R_1, L1R2L_1R_2, and L2R1L_2R_1. If we choose L1R1L_1R_1 first, we can find the following residual path in the next round:

s→L2→R1→L1→R2→t. s\to L_2\to R_1\to L_1\to R_2\to t.

Here, R1→L1R_1\to L_1 is a reverse edge. Using it cancels the original L1R1L_1R_1 pair. We then replace it with L2R1L_2R_1 and L1R2L_1R_2, increasing the matching size from 1 to 2.

This also explains why we cannot record a pairing edge as part of the final answer just because it has carried flow at some point. We need to finish the maximum flow algorithm first, then check the residual capacities.

Complete code

The following code uses C++17 and keeps the e + id adjacency-list structure. The input starts with nL nR m, followed by mm lines of u v, meaning that left vertex u can be paired with right vertex v. The two sides are numbered within [1,nL] and [1,nR] respectively. The first output line gives the maximum matching size, and each following line gives one matched pair.

A pairing edge starts with capacity 1, and its reverse edge starts with capacity 0. So at the end, e[idx ^ 1].c == 1 means this edge has been selected. The arrays are sized using id.size(), which includes both sides and the extra source and sink. If we only allocate n+1 entries based on the original problem, right-side vertices can easily go out of bounds.

The same core code also works for general maximum flow. We only need to set the source and sink again and build the graph with the given capacities. Capacities must be non-negative, and the total flow must fit in ll. In a deep graph, the recursion depth can reach O(V)O(V), so keep an eye on stack space when the input is very large.

If a problem says “the flow through vertex u cannot exceed b”, we can split it into u_in and u_out, with an edge of capacity b between them. Original incoming edges connect to u_in, and outgoing edges start from u_out. All flow through this vertex is then limited by the edge in the middle. This turns a vertex capacity into an edge capacity.

Complexity and matching with a threshold

In a general network, finding a blocking flow takes at most O(E)O(E) augmentations, and each path has length O(V)O(V). The current-edge pointers limit scans of failed edges to O(E)O(E) in each round. With at most O(V)O(V) rounds of building the level graph, the time complexity is O(V2E)O(V^2E) and the space complexity is O(V+E)O(V+E).

For the standard unit network used in bipartite matching, the time bound improves to O(EV)O(E\sqrt V), where EE includes the edges connected to the source and sink. This bound depends on the structure of the matching network. We cannot apply it directly to every network whose “edge capacities are all 1”.

For the kind of problem we discussed earlier, where each pair has a time d and we want to finish the whole matching as early as possible, we can still use this construction. To check an answer lim, only add pairing edges with d <= lim, then see whether the maximum flow equals the number of vertices that need to be matched. As lim increases, more edges become available. The condition is monotonic, so we can binary-search the answer.

For every check, rebuild the graph or restore the initial residual capacities. Flow left over from the previous check will affect the next result.

What we are minimising here is the largest time among all selected pairs. If the problem changes to minimising total cost, the objective is different. We will handle that in the next post on min-cost flow and weighted matching.
