Min-Cost Flow & Weighted Bipartite Matching

Read the original Chinese version

The previous post turned bipartite matching into a maximum flow problem. One unit of flow represents one matched pair, and the capacity limits ensure that each vertex is chosen at most once. If different pairs also give different profits, which edges we choose will affect the answer as well.

Min-cost flow gives each edge a cost per unit of flow. We still augment the flow and use reverse edges, but now there is a cost to keep track of when finding a path.

First, be clear about the objective

Minimum-cost maximum flow means maximising the flow first, then minimising the cost. Suppose two solutions send flows of 33 and 44. Even if the second one costs more, we still choose the solution with a flow of 44.

Some problems already require us to complete exactly KK tasks. In that case, the flow is fixed at KK, and we only compare costs. If the maximum possible flow is less than KK, there is no solution. We cannot use the cost found so far as the answer.

Let the flow on an original edge ee be fef_e, and let wew_e be its cost per unit. The total cost is

∑e∈Efewe. \sum_{e\in E} f_e w_e.

Here, wew_e is the cost of each unit of flow. If one augmentation sends 33 units along a path with a cost of 55 per unit, the answer should increase by 1515.

We can keep the adjacency list from before and just add w to Edge. c still represents the residual capacity. Adding a cost does not mean we can mix the two up.

Reverse edges need to refund the cost too

In maximum flow, following a reverse edge lets us undo flow that we sent earlier. Now, sending one unit along the original edge costs ww, so undoing it should refund ww. That is why the reverse edge has a cost of −w-w.

The reverse edge still starts with a capacity of 0. We can only undo as much flow as has passed through the forward edge. If the input graph already contains two edges in opposite directions, call add() separately for each one, giving each its own reverse edge in the residual network.

This also makes shortest paths a little more complicated. Even if all input costs are non-negative, an augmentation can create reverse edges with positive residual capacity and negative costs. We cannot simply give the original costs to Dijkstra.

Start with shortest augmenting paths

EK uses BFS to find an augmenting path with the fewest edges. For min-cost flow, we compare the sum of the costs along the path, so we need to find a source-to-sink path with the lowest cost in the residual network.

Whenever we find a path, take the smallest residual capacity along it as the amount to send, then update the forward and reverse edges. The path may include reverse edges, which cancel the costs of some earlier choices.

As long as the initial residual network has no negative-cost cycles, augmenting along a shortest-cost path keeps the cost optimal for the current amount of flow. Continue until the sink is unreachable, and we get minimum-cost maximum flow.

For a fixed amount of flow, the difference between two feasible solutions can be split into cycles in the residual network. If a cheaper solution exists, at least one of these cycles has a negative cost. Conversely, adjusting the flow along a negative-cost cycle reduces the cost without changing the amount of flow. Shortest-path augmentation keeps the residual network free of negative-cost cycles, which guarantees optimality at each step. The potentials below give us another way to understand this condition.

The most direct implementation runs SPFA in every round, since it can handle negative-cost edges. SPFA has a worst-case complexity of O(VE)O(VE), and running it for every augmentation means spending a lot of time repeating shortest-path searches. Here, we use an initial SPFA followed by Dijkstra with potentials. Reverse edges are maintained in exactly the same way as before.

Adjust edge costs with potentials

Maintain a potential h[u] for each vertex, and use the following edge cost during the search:

w′(u,v)=w(u,v)+h[u]−h[v]. w'(u,v)=w(u,v)+h[u]-h[v].

First, let us check whether this changes the shortest path. Along a path from ss to tt, the potential of each intermediate vertex is added once and subtracted once. They cancel out, leaving only

∑w′=∑w+h[s]−h[t]. \sum w' = \sum w+h[s]-h[t].

Every source-to-sink path has the same value added to its cost, so their order by cost stays the same. Now, as long as the w′w' values used in the search are non-negative, we can use Dijkstra.

For the first round, use SPFA to find the shortest distance from the source to each reachable vertex, and set h[v] to that distance. The triangle inequality for shortest paths gives

h[v]≤h[u]+w(u,v), h[v]\le h[u]+w(u,v),

so every edge with positive residual capacity in the reachable part satisfies w′(u,v)≥0w'(u,v)\ge0. If all edges with positive residual capacity have non-negative costs at the start, we can simply set every potential to 0.

The reverse edges created by augmentation also have an adjusted cost of 0, so we can keep using Dijkstra in the next round.

Add weights to bipartite matching

Keep the numbering of the source, left and right vertices, and sink from the previous post. If the pair (u,v)(u,v) gives a profit of weight, just set the cost of its edge to -weight.

Edge Capacity Cost
s -> u 1 0
u -> nL+v 1 -weight
nL+v -> t 1 0

One unit of flow represents one matched pair, and the total profit is -cost. Initially, the edges with positive residual capacity go from the source to the left side, then to the right side, and finally to the sink. There are no directed cycles, so there are no negative-cost cycles either.

The edges from the source to the left side and from the right side to the sink all have capacity 1, so no vertex can belong to two matched pairs. The capacities are integers, so the amounts sent during augmentation are integers too. The net flow on a candidate pair edge can only be 0 or 1. Conversely, any valid matching can send one unit of flow along the corresponding source-to-sink path for each pair. The two kinds of solutions correspond one to one.

At this point, we should not rush to send as much flow as possible. Whether the problem wants the most pairs or the highest total profit changes when we should stop.

Consider three allowed pairs: L1R1L_1R_1 gives a profit of 1010, while L1R2L_1R_2 and L2R1L_2R_1 each give 44.

Choosing only L1R1L_1R_1 gives a total profit of 1010. Switching to the other two pairs increases the matching size to 22, but lowers the profit to 88. This difference can appear even when all edge weights are positive.

After choosing the edge with profit 1010, the next augmentation goes through its reverse edge. It adds two new pairs and removes the old one, with an original path cost of

−4+10−4=2. -4+10-4=2.

This augmentation increases the matching size by one while reducing the profit by two. With this calculation, the two objectives become clear.

Objective What to do
Maximise total profit; choosing fewer pairs is allowed Augment only when path_cost < 0
Maximise the number of pairs first, then total profit Keep augmenting until no path remains
Match exactly KK pairs with the highest total profit Augment up to KK, then check whether it was reached

The marginal cost of shortest augmenting paths never decreases, so the optional matching mode can stop when the shortest path has a non-negative cost. It skips augmentations with a cost of 0, so it does not guarantee the most pairs among matchings with the same total profit.

An edge used during an earlier augmentation may later be undone, so we cannot permanently add it to the answer just because flow passed through it once.

Complexity and when to use it

Let EE be the number of original edges, VV the number of vertices, and AA the number of successful augmentations. When SPFA is needed, initialisation takes O(VE)O(VE) in the worst case; otherwise, it only takes O(V+E)O(V+E). This implementation allows duplicate entries in the priority queue, so each Dijkstra run takes O(V+Elog⁡(E+2))O(V+E\log(E+2)). There are at most A+1A+1 searches in total, and the space complexity is O(V+E)O(V+E). In bipartite matching, each augmentation adds one pair, so A≤min⁡(nL,nR)A\le\min(n_L,n_R).

The template requires non-negative integer capacities, different source and sink vertices, and an initial residual network with no negative-cost cycles. A problem with negative-cost cycles may still have a finite optimal solution, but it needs extra handling. This template does not include cycle cancellation.

Both capacities and costs use long long, but intermediate calculations such as pushed * path_cost must still fit within the type. The absolute values of finite distances and potentials must also stay below INF. Call init_graph() before each test case. When comparing different objectives on the same graph, rebuild it or restore the initial e. Calling the function again directly uses the residual capacities already changed by the previous call, and returns only the flow and cost added in the new call.
