The Duality Behind Max-Flow Min-Cut, König and Dilworth

Read the original Chinese version

When I was learning the max-flow min-cut theorem, I kept feeling that it was a bit like König’s theorem and Dilworth’s theorem. One is about flow, one is about matching, and the other is about partially ordered sets. Yet they all end up with “a maximum equals a minimum”.

They are all min-max theorems in combinatorial optimisation, which makes the connection easier to understand.

Theorem What do we maximise? What do we minimise?
Max-flow min-cut Flow from the source to the sink Capacity of a cut separating the source and sink
König, for bipartite graphs Number of edges in a matching Number of vertices in a vertex cover
Dilworth, for finite partially ordered sets Number of elements in an antichain Number of chains needed to partition all elements

Start with the easier side to prove

The value of any flow cannot exceed the capacity of any cut. Once we separate the source and sink, the flow has to cross the cut, and the capacity of the cut limits how much can get through.

Matching and vertex cover have a similar relationship. A vertex cover requires at least one endpoint of every edge to be selected. The edges in a matching share no endpoints, so covering these edges requires us to select at least one vertex for each of them. Therefore, for any matching MM and any vertex cover CC, we have

|M|≤|C|. |M|\le |C|.

In a partially ordered set, every pair of elements in a chain is comparable, while every pair of distinct elements in an antichain is incomparable. A chain can contain at most one element of an antichain. If we have partitioned all elements into kk chains, any antichain has size at most kk.

These inequalities all serve the same purpose. Finding a matching of size 55 only tells us that the answer is at least 55. If we also find a vertex cover of size 55, we immediately know the answer.

This is the most intuitive use of duality. One side gives us a feasible solution, and the other proves that it cannot be improved any further. The difficult part is whether we can always find solutions with the same value on both sides.

Once max flow finishes, the min cut is already in the residual graph

We will use the notation from Network Flow Basics. When there is no augmenting path, start a search from ss, following only edges with positive residual capacity. Call the set of reachable vertices SS, and put the remaining vertices in TT.

At this point, t∈Tt\in T. Every edge from SS to TT in the original graph must be full; otherwise, we could still cross it. Every edge from TT to SS in the original graph must carry no flow; otherwise, its reverse edge in the residual graph would also let us move from SS to TT.

Adding up the flow conservation equations for the vertices in SS, the internal edges cancel out, leaving

|f|=f(S,T)−f(T,S)=c(S,T). |f|=f(S,T)-f(T,S)=c(S,T).

We have found a flow and a cut with the same value. Since any flow is bounded by any cut, both must be optimal.

There is no requirement here for capacities to be integers. Integer capacities give us a separate property: an integer maximum flow exists. We will need this when interpreting flow as a matching.

König’s theorem follows directly from min cut

Let the two sides of a bipartite graph be L,RL,R. Build the following network.

Edge Capacity
s→us\to u, where u∈Lu\in L 11
u→vu\to v, where (u,v)(u,v) is an edge in the original graph INFINF
v→tv\to t, where v∈Rv\in R 11

Compared with the construction in Bipartite Matching, the capacities of the middle edges have changed to INFINF. The edges at both ends still limit each vertex to at most one unit of flow, so an integer maximum flow still corresponds to a maximum matching.

Taking INF=|L|+|R|+1INF=|L|+|R|+1 is enough. Cutting only the outgoing edges of the source already costs at most |L||L|, so a minimum cut will never choose to cut a middle edge with capacity INFINF.

Let SS be the source side of a minimum cut, and choose

C=(L\S)∪(R∩S). C=(L\setminus S)\cup(R\cap S).

In other words, choose the unreachable vertices on the left and the reachable vertices on the right.

If neither endpoint of an original edge (u,v)(u,v) were selected, then u∈Su\in S and v∉Sv\notin S. This edge would cross the cut and contribute INFINF, contradicting what we just showed. Therefore, CC covers every edge.

The unit-capacity edges crossing the cut correspond exactly to the selected vertices, so

|C|=min cut=max flow=|M|. |C|=\text{min cut}=\text{max flow}=|M|.

Every vertex cover also has at least |M||M| vertices, which proves König’s theorem. Conversely, given a vertex cover CC, we can take S={s}∪(L\C)∪(R∩C)S=\{s\}\cup(L\setminus C)\cup(R\cap C) to construct a cut of capacity |C||C|.

Using the same e + id adjacency list as before, we can recover this vertex cover directly after running max flow on the network above. The left vertices are numbered 1..nL, and the right vertices are numbered nL+1..nL+nR.

Dilworth connects to bipartite matching too

Suppose a finite partially ordered set has nn elements. Make a left and a right copy of each element xx, called xL,xRx_L,x_R. Add an edge xL→yRx_L\to y_R if and only if x<yx<y. We use the strict relation here, so there is no edge xL→xRx_L\to x_R.

A matching edge xL→yRx_L\to y_R means placing yy directly after xx. The matching ensures that each element has at most one predecessor and one successor, while the strict partial order prevents cycles. Therefore, a matching of size mm connects the nn elements into n−mn-m chains.

Conversely, if we have a partition into kk chains, connecting consecutive elements in each chain gives us n−kn-k matching edges. So, if the maximum matching has size mm, then

minimum chain partition size=n−m. \text{minimum chain partition size}=n-m.

We still need an antichain of the same size.

By König’s theorem, the bipartite graph of copies has a vertex cover CC of size mm. Keep the original elements whose left and right copies are both outside CC, giving the set

A={x∣xL∉C,xR∉C}. A=\{x\mid x_L\notin C,\ x_R\notin C\}.

If there were elements x<yx<y in AA, neither endpoint of the edge xL→yRx_L\to y_R would be covered. Therefore, AA must be an antichain.

CC contains only mm copies, so it excludes at most mm original elements. This gives |A|≥n−m|A|\ge n-m. We have also already constructed n−mn-m chains, and each chain can contain at most one antichain element, so |A|≤n−m|A|\le n-m. Putting the two sides together gives

maximum antichain size=minimum chain partition size=n−m. \boxed{\begin{gathered} \text{maximum antichain size}\\ =\text{minimum chain partition size}\\ =n-m \end{gathered}}.

For example, suppose a<b<da<b<d and a<c<da<c<d, while b,cb,c are incomparable. The matching aLbR,bLdRa_Lb_R,b_Ld_R gives two chains, (a,b,d)(a,b,d) and (c)(c). The vertex cover {aL,dR}\{a_L,d_R\} leaves the antichain {b,c}\{b,c\}. Both the number of chains and the antichain size are 22.

This construction needs all comparable pairs. If the partial order comes from reachability in a DAG, we need to consider the transitive closure. For example, suppose the original graph only has

a→c,b→c,c→d,c→e. a\to c,\quad b\to c,\quad c\to d,\quad c\to e.

If we build the bipartite graph using only these original edges, the maximum matching has size 22, giving a minimum vertex-disjoint path cover of size 5−2=35-2=3. If we use reachability instead, we can also use b<db<d and partition the elements into two chains, (a,c,e)(a,c,e) and (b,d)(b,d). Chains can skip intermediate elements, while vertex-disjoint paths must actually pass through them along the original edges. These two constructions answer different questions.

Linear programming writes this connection as formulas

First, write matching as an optimisation problem. Give each edge a variable xex_e, which is 11 if we select the edge and 00 otherwise. Each vertex can belong to at most one matching edge, so we have

max⁡∑e∈Exe,∑e∋vxe≤1(∀v),xe∈{0,1}. \max\sum_{e\in E}x_e, \qquad \sum_{e\ni v}x_e\le 1\quad(\forall v), \qquad x_e\in\{0,1\}.

Relaxing the last condition to xe≥0x_e\ge 0 gives a linear programming relaxation. The constraints at the endpoints of each edge already ensure xe≤1x_e\le1. Its dual is

min⁡∑v∈Vyv,yu+yv≥1(∀uv∈E),yv≥0. \min\sum_{v\in V}y_v, \qquad y_u+y_v\ge 1\quad(\forall uv\in E), \qquad y_v\ge 0.

If yvy_v is 00 or 11, it tells us exactly whether vertex vv is selected. The constraints require at least one endpoint of every edge to be selected. This is vertex cover.

We can also calculate directly why the two expressions bound each other.

∑uv∈Exuv≤∑uv∈Exuv(yu+yv)=∑v∈Vyv∑e∋vxe≤∑v∈Vyv. \sum_{uv\in E}x_{uv} \le\sum_{uv\in E}x_{uv}(y_u+y_v) =\sum_{v\in V}y_v\sum_{e\ni v}x_e \le\sum_{v\in V}y_v.

This is called weak duality. Strong duality goes further and guarantees that the optimal values of these two linear programs are equal.

But they now allow fractions. To get back to actual matchings and vertex covers, we still need to show that allowing fractions does not change the optimal values. Bipartite graphs have exactly this integrality property, which follows from the total unimodularity of their vertex-edge incidence matrices. This property requires every square submatrix to have a determinant in {−1,0,1}\{-1,0,1\}. Together with the integer right-hand sides here, it means both problems have integer optimal solutions. The integer variables for vertex cover can also be capped so that they only take values of 00 or 11.

This does not necessarily hold for general graphs. Try a triangle.

Problem Select it or leave it out Fractions allowed
Maximum matching 11 Assign 1/21/2 to every edge; the optimum is 3/23/2
Minimum vertex cover 22 Assign 1/21/2 to every vertex; the optimum is 3/23/2

The two linear programs still satisfy strong duality, but the actual matching and vertex cover have different values. This is where the “bipartite graph” condition in König’s theorem matters.

Max-flow min-cut can also be proved through linear programming duality. Strictly speaking, the dual we first write down contains real-valued vertex potential variables. We still need to prove that we can extract a cut with the same value from an optimal dual solution. Only then have we connected the optimal value in the linear program to a cut we can actually find in the graph.
