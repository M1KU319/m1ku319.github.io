Network Flow Basics & Maximum Flow

Read the original Chinese version

We can start by thinking of network flow as moving goods through a directed graph. The goods travel from a starting point to a destination along different routes, and each road has a limit on how much it can carry. Maximum flow asks how much we can send in total. If each road also charges a fee, we get to min-cost flow.

The basic ideas of network flow

Given a directed graph, choose a source ss and a sink tt. Each edge has a capacity c(u,v)c(u,v), which is the most flow it can carry. We want to send as much flow as possible from ss to tt.

The source is where flow starts, the sink is where it ends, and the other vertices pass it along. For example, suppose the only path is s→a→ts\to a\to t, with capacities 33 and 22. We can send at most 22 units. A capacity of 33 does not mean we have to send 33 units; it is just the upper limit for that edge.

Write the actual flow through an edge as f(u,v)f(u,v). It must satisfy

0≤f(u,v)≤c(u,v). 0\le f(u,v)\le c(u,v).

Intermediate vertices must also satisfy flow conservation. At every vertex except the source and sink, the total incoming flow equals the total outgoing flow. Flow cannot appear out of nowhere, and we cannot leave some of it at an intermediate vertex.

If we write an original edge as ee and its flow as fef_e, then every intermediate vertex vv satisfies

∑e:e enters vfe=∑e:e leaves vfe. \sum_{e:\,e\text{ enters }v}f_e =\sum_{e:\,e\text{ leaves }v}f_e.

The total flow is the net flow leaving the source, which also equals the net flow entering the sink. We can use several paths at once. If several paths share an edge, their combined flow through that edge must still stay within its capacity.

A flow assignment that satisfies the capacity constraints and flow conservation is called a feasible flow. Its value is usually written as |f||f|. We only count the net flow leaving the source, rather than adding up the flow on every edge. The same goods do not become several batches just because they pass through several roads. A maximum flow is a feasible flow with the largest possible |f||f|.

Adding a cost to each edge

If different routes have different costs, give each original edge ee a cost per unit wew_e. Sending fef_e units through it costs fewef_e w_e, so the total cost is

cost⁡(f)=∑e∈Efewe. \operatorname{cost}(f)=\sum_{e\in E}f_e w_e.

For example, suppose the two edges on s→a→ts\to a\to t cost 22 and 33 per unit. Sending one unit costs 55, and sending two costs 1010. Capacity limits how much we can send, while cost affects which route we choose.

There are two common goals to distinguish here. Min-cost flow with a fixed value asks us to send exactly KK units and find the cheapest way to do so. If the maximum flow is less than KK, there is no solution. Min-cost maximum flow first maximises the flow, then minimises the cost among all maximum flows. We cannot send less just to make it cheaper.

Then Min-Cost Flow & Weighted Bipartite Matching adds costs. The final post, The Duality Behind Max-Flow Min-Cut, König and Dilworth, connects the reasons why these solutions are optimal.

Starting with one path

First, find a path from ss to tt. If the remaining capacities along it are 5,3,75,3,7, we can send at most 33 units this time. The smallest remaining capacity limits the whole path. This is usually called the bottleneck capacity.

After sending that flow, we look for another path. This is where things get interesting.

Reverse edges let us change earlier choices

Consider four vertices s,a,b,ts,a,b,t. The original graph has five edges: s→as\to a, s→bs\to b, a→ba\to b, a→ta\to t, and b→tb\to t. Every edge has capacity 11.

Suppose we first choose s→a→b→ts\to a\to b\to t. All three edges become full. If we only look at the remaining capacities of the original edges, ss can still reach bb, but bb can no longer reach tt. It looks as if we can only send 11 unit.

But choosing s→a→ts\to a\to t and s→b→ts\to b\to t clearly gives us 22. We need a way to adjust our first choice.

Once 11 unit has flowed through a→ba\to b, we also allow 11 unit to travel along b→ab\to a. Using this reverse edge removes 11 unit of the earlier flow on a→ba\to b.

We can now find another path:

s→b→a→t. s\to b\to a\to t.

We add 11 unit to both s→bs\to b and a→ta\to t, and remove 11 unit from a→ba\to b. What remains is exactly the two paths carrying 11 unit each, giving a total flow of 22. Flow conservation still holds at every intermediate vertex along the new path.

A reverse edge records how much of an earlier flow we can undo. An original edge with capacity cc and current flow ff has two residual edges: a forward edge with remaining capacity c−fc-f, and a reverse edge with remaining capacity ff. Keeping only edges with positive residual capacity gives us the residual network. An ss-to-tt path in this network is called an augmenting path.

Ford-Fulkerson

Ford-Fulkerson is quite straightforward. Find an augmenting path in the residual network, send its bottleneck capacity along it, and keep looking until no such path remains.

We can use DFS to find a path. In dfs(u, lim), lim is the most flow the current path can still carry. Return it when we reach the sink. When moving to the next edge, pass min(lim, e[idx].c), then use any positive flow returned to update the residual capacities.

There is an easy mistake to make here. If one recursive call returns 0, only that branch has failed; we should keep trying the other outgoing edges. Return early only after finding an augmenting path. If every branch fails, return 0 at the end of the function. Also, clear vis before every new search. A vertex visited last time may still be useful this time.

Assume all capacities are integers and the maximum flow is FF. Every successful augmentation adds at least 11, so there are at most FF successful augmentations. Each search takes O(V+E)O(V+E). Including the final failed search, the total upper bound is O((F+1)(V+E))O((F+1)(V+E)), often written as O(EF)O(EF). This bound depends on the numerical value of the flow, so it can be slow when capacities are large.

With irrational capacities, Ford-Fulkerson may not even terminate if paths are chosen arbitrarily. Edmonds-Karp specifies how to choose paths, giving a complexity bound in terms of the numbers of vertices and edges.

Edmonds-Karp

Edmonds-Karp, or EK, uses BFS to find each augmenting path. Residual capacity only decides whether an edge can be used. BFS builds layers by the number of edges, so it finds a path with the fewest edges.

For example, one path has two edges, each with remaining capacity 11. Another has three edges, each with remaining capacity 100100. EK chooses the first one. Once the path is fixed, we take its smallest residual capacity to decide how much flow to send.

BFS processes vertices in queue order. When a vertex is reached, all vertices reachable using fewer edges have already been discovered. Expanding from a vertex at distance dd, any newly discovered vertex belongs to layer d+1d+1. We are not sorting by capacity, and we do not need a priority queue.

Recording the path and its bottleneck

Use pre[v] to store the index of the edge entering vv. Initialise it to -1, which also marks the vertex as unvisited. Mark the source in advance, or a residual reverse edge might put it back in the queue.

Why store an edge index? There may be parallel edges between the same two vertices, so the previous vertex alone cannot tell us which edge we used. Given an edge index idx, its starting vertex is e[idx ^ 1].v.

We keep using the e + id adjacency list. e stores all edges, and id[u] stores the indices of the edges leaving uu. Each call to add an edge inserts its forward and reverse edges consecutively, so idx ^ 1 switches between them.

The input starts with n m s t, followed by mm lines of u v c. Vertices are numbered [1,n]. The source and sink must be different, capacities must be non-negative integers, and both the capacities and the answer must fit in long long.

If the original graph contains both u→vu\to v and v→uv\to u, call add() separately for each one. This stores four edges in total. Each original edge has its own residual reverse edge; the two original edges must not be treated as one pair.

EK takes O(VE2)O(VE^2) time and O(V+E)O(V+E) space. Roughly speaking, the shortest BFS distance to each vertex never decreases as we augment. Before the same directed residual edge can become full again, the layer of its starting vertex must increase. An edge can therefore be a bottleneck at most O(V)O(V) times, giving O(VE)O(VE) augmentations in total. Multiplying by the cost of each BFS gives this bound, usually ignoring the cost of initialising isolated vertices.

Why is the flow maximum when no augmenting path remains?

Split all vertices into two sets S,TS,T, with s∈Ss\in S and t∈Tt\in T. This is an ss-tt cut. Its capacity only counts original edges directed from SS to TT:

c(S,T)=∑u∈S,v∈Tc(u,v). c(S,T)=\sum_{u\in S,\,v\in T}c(u,v).

Adding up the flow-balance equations over the vertices in SS, the internal edges cancel, leaving only the net flow across the boundary:

|f|=f(S,T)−f(T,S)≤c(S,T). |f|=f(S,T)-f(T,S)\le c(S,T).

So any flow is bounded by the capacity of any cut. We must subtract the flow crossing back from TT to SS, rather than just counting what leaves SS.

When no augmenting path remains, let SS be the vertices still reachable from ss in the residual network, and put all other vertices in TT. The sink is unreachable, so it belongs to TT.

Every original edge from SS to TT is full; otherwise, we could reach further along its forward residual edge. Every original edge from TT to SS carries zero flow; otherwise, its reverse residual edge would let us move from SS to TT. Therefore,

|f|=c(S,T)−0=c(S,T). |f|=c(S,T)-0=c(S,T).

We already showed that every flow is bounded by every cut. Now their values are equal, so the current flow is a maximum flow and this cut is a minimum cut. The max-flow min-cut theorem turns “we cannot find another path” into a proof of optimality that we can actually check.

EK augments along just one path per BFS. Could we reuse the layers found by the same BFS a few more times? We will pick this up in Dinic & Maximum Bipartite Matching.
